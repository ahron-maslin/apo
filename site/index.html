How it works

Agents ask. You answer from one queue. The repo keeps the answer.

  1. 1

    An agent files a request and keeps going

    apo gives every Claude Code session an MCP server to ask through. A decision carries a two-sentence summary, the options with what the agent will do for each and whether it can be undone, a recommendation with how sure the agent is, and what's blocked versus safe to continue. Then the agent gets on with the safe part.

    Some things need your hands: a DNS record, a merge, an API key. For those the agent files an action with a link, the steps, values to copy, and a check apo runs when you press Done.

  2. 2

    You answer from one queue

    The dashboard's Now page lists what's waiting on you across every project, ranked by how blocked each agent is and how long it has waited. Most answers take one key. With a few minutes free, a lightning round fits your moves into 2, 5 or 15 minutes, one card at a time.

    You can also write your own answer, attach a screenshot, or say you need more information first.

    • yAccept the agent's suggestion
    • 1to9Pick an option
    • eMark an action done
    • sSnooze it
    • tStart a 5-minute round
  3. 3

    The answer is written into the repo

    apo keeps .claude/decisions/ up to date in each project: an INDEX.md, plus one markdown file per request with the question, your answer and the agent's handoff notes. A file is greppable, survives a clone, and sits next to the work it led to.

    Secrets you type into an action go to an encrypted store on your machine and never reach these files.

  4. 4

    The next session picks it up

    If the session that asked is still open, it gets the answer with your next prompt there. A new session in that repo is told at start that answers are waiting, and /decisions works through them. If nothing picks an answer up within an hour, it comes back to your queue with a button that starts a background session to apply it.

    Each answer is tracked from pending to delivered to applied, so you can see which ones reached an agent.

What else it does

Fewer interruptions, and a record of what was decided

  • Accept in bulk

    Accept every suggestion an agent is at least 85% sure of and has marked easy to undo, after you've looked over the list.

  • Standing rules

    Write down the answers you'd give every time. Agents read them from .claude/decisions/POLICY.md and follow them instead of asking.

  • Goals

    A result you want, with a checklist. Each step belongs to you, an agent or someone outside. Agent steps reach the repo as tasks the next session picks up.

  • Every session, live

    Status comes from Claude Code's own hooks and its list of running sessions, so watching your sessions spends no tokens.

  • Snooze

    Put an item away for 2 hours, until tomorrow, or until the agent that asked is actually stuck on it.

  • Notifications

    Off until you turn them on. Then an item interrupts you only after it has waited a while, at most 6 times a day, inside the hours you set.

  • Search and weekly reports

    Search every question, answer, session recap and goal. A weekly report per project shows what got done and decided, and how long agents waited on you.

  • Linear, if you use it

    Mirror requests as Linear issues and answer with a comment, or plan a goal as an issue with sub-issues. It's off unless you connect it.

  • Local

    No account, no telemetry and no AI of its own. The dashboard listens on 127.0.0.1 and keeps its data in a SQLite file on your machine.

Who it's for

One person running many Claude Code sessions

You have sessions going in several projects and don't watch any one terminal, so a question from one of them waits until you happen to look. With apo it goes into a queue, and the agent carries on with the parts that don't depend on your answer. Sessions show up however you started them: in a terminal, in VS Code or in the background.

It fits if

  • you work across more than one repo at a time
  • you'd rather clear ten questions in five minutes than answer one every few minutes
  • you want decisions written down in the repo, beside the work they led to

Look elsewhere if you want

  • a shared workspace for a team. apo is for one person on one machine, with no accounts.
  • agents run in the cloud for you. apo watches sessions you start and hosts none.
  • support for agent CLIs other than Claude Code

Next to other tools

Where apo fits among agent tools

Other tools start and host your agents, or put a live session on your phone. apo watches the Claude Code sessions you already run, keeps every answer in the repo, and runs no AI of its own. It works alongside most of them.

  • Claude Code's agent view and Remote Control

    What they doAnthropic's own tools. Agent view lists your background sessions on one terminal screen. Remote Control lets you drive a session from the browser or your phone.

    What apo addsIt also sees sessions started in a terminal or VS Code, across every project. An answer outlives the session, because it's written into the repo.

  • Session runners such as Conductor, Claude Squad and CCManager

    What they doStart each agent in its own worktree and run it inside their app or terminal.

    What apo addsapo doesn't start or wrap your agents. It watches the sessions you already run, however you started them, and gives their questions one queue.

  • Phone apps such as Happy and HAPI

    What they doPut a live session on your phone, so you can answer its prompts from anywhere.

    What apo addsThe session doesn't have to still be open. Answers are written into the repo, where whichever session comes next picks them up.

  • Team platforms such as HumanLayer and GitHub Agent HQ

    What they doShared workspaces where a team assigns agent work and reviews it.

    What apo addsapo is for one person on one machine. There's no account or server, and nothing leaves your computer unless you connect Linear.

Install

Install in three commands

  1. 1
    $pipx install getapo

    The package is called getapo on PyPI. It installs the apo command in its own environment.

  2. 2
    $apo init

    Creates the local database and connects apo to Claude Code. It asks where your projects live and whether to connect Linear, which you can skip.

  3. 3
    $claude

    Start a new Claude Code session in one of your project folders. Sessions that were already running don't get apo's tools until you restart them.

Then open the dashboard

$apo dashboard

What apo init changes

  • Registers apo's MCP server with Claude Code for your user, so every session can file requests and gets a short note on when to.
  • Adds hook entries to ~/.claude/settings.json, after making a backup of it.
  • Installs the /decisions skill.
